## 1. 结论（先看这）

你们已经不是「从零做官网」，而是：**公开品牌站 + 私密客户门户** 双层产品，技术底座（Vinext / Cloudflare Worker / D1 / R2、OTP 登录、案件/报告/精卵库授权）比多数代孕中介宣传站成熟得多。

当前最大缺口不是再堆首页文案，而是：

1. **公开转化路径过窄**：首页几乎只导向 `/portal`，缺少「套餐/费用对照」的轻量出口（可做成 PDF 或登录后可见，不必做成竞品那种报价传单页）。  
2. **私密部署与真实客户治理未收口**：`docs/implementation.md` 仍标未完成「精确源码提交、私有部署、正式交接」；真实客户上线前的法务/存储/留存未批。  
3. **工作区有未提交改动**：`app/product.css`、`components/product/portal.tsx`、`lib/server.ts` 已修改，`scripts/` 未跟踪——建议先整理提交，避免试点环境漂移。  
4. **与竞品文案包要对齐策略**：竞品靠「无限次 / 包性别 / 全退 / 标价」转化；你们规格明确禁止公开报价与包成功——正确。建议把「透明费用」放进**门户内方案页或授权下载**，而不是直接抄竞品首页。

## 4. 优先建议（按性价比排序）

### P0 — 本周该做

1. **清理并提交本地改动**  
   看清 `portal.tsx` / `server.ts` / `product.css` 改了什么；`scripts/` 该进库就进库，不该进就加 ignore。

2. **补一条公开转化，但不破合规**  
   在 `#contact` 或 `#options` 增加次 CTA：「获取套餐对照与费用边界说明（PDF）」→ 邮件/微信收集，或登录后下载。文案直接剪裁此前《官网文案包》B/C，**去掉必成/全退**。

3. **收口私有部署清单**  
   按 `implementation.md` 第 7 步：固定 commit、私有 Sites 策略、管理员邮箱、备份与保留策略草案。

### P1 — 产品增强（门户 > 首页）

4. **门户「方案摘要」页**  
   标准 / 供卵 / PGT 升级三档 + 含/不含 + 付款节点（仅对已批准客户可见）。这比再加公开营销页更符合现有架构。

5. **案件阶段与公开旅程对齐**  
   DB `cases.stage` 默认 `assessment`；把门户阶段文案与首页四步旅程用同一套词汇，降低客户认知成本。

6. **精卵库授权体验**  
   首页已说明「获批后开放」；建议在门户 pending 状态给明确等待文案与预计处理时间，减少「是不是网站坏了」的咨询。

### P2 — 体验与工程

7. 首页 `page.tsx` 仍是超长单文件 + 大量内联 `t()`——可抽 `content/home.ts` 方便运营改字。  
8. Vinext `1.0.0-beta.5`：锁定变更日志，升级前跑现有 tests。  
9. 附件无杀毒（文档已写明）——真实客户前必须有替代控制（类型/大小/人工复核已有，可再加强）。  
10. 联系方式写死在 `page.tsx`：可迁到配置/环境变量，避免改代码发版。
