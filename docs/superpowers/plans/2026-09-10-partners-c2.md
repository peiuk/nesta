# 合作方台账（C2）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `/admin` 增加 IVF 诊所与月子中心名录，并支持每个案件各绑定最多一家；客户门户不展示。

**Architecture:** Approach A——新表 `partners`；`cases` 增加可空 `ivf_partner_id` / `postpartum_partner_id`；纯函数校验 kind/active；admin-only API + `/admin` 侧栏与案件详情绑定 UI。

**Tech Stack:** Vinext/Cloudflare Worker、D1、现有 `admin-workspace` / `portal` CaseDetail、`node --test`、`tsc`。

## Global Constraints

- 规格：`docs/superpowers/specs/2026-09-10-partners-c2-design.md`
- 类型仅 `ivf` | `postpartum`；每案每类最多一家；仅 admin 可见
- 不做：客户展示、同类型多家、C3 证件、批量导入、双语文案字段
- 分支：`main`；提交用 PowerShell 友好的 `git commit -m "..."`；**仅在用户要求时 commit**
- 验证：相关 `node --test`、`npx tsc --noEmit`
- Shell 在本机需 `required_permissions: ["all"]`（sandbox 不可用）

**Interfaces:**

- [ ] **Step 1–4: RED → 实现 → GREEN**

### Task 3: Server API

**Files:**
- Modify: `lib/server.ts`

**Interfaces:**
- Consumes: Task 1 列/表 + Task 2 纯函数
- Produces: 规格中的 partners 与 case partners 端点；admin 读案件含 `partners` 摘要

- [ ] **Step 1: `GET/POST partners`，`POST partners/:id`**

- admin only
- list：可选 query `kind`、`status`（缺省 all），`ORDER BY name LIMIT 300`
- create：必填 `kind`+`name`；其余默认 `''`；status `active`
- update：字段 + `status`；`reason` 进审计
- 审计动作：`partner.create` / `partner.update`

- [ ] **Step 2: `POST cases/:id/partners`**

- admin only；`member`/`admin` 校验：用现有 admin(a) + case 存在
- body：`ivf_partner_id?`、`postpartum_partner_id?`、`reason`
- 对每个出现的键：normalize → null 则清空该列；否则 load partner，用 `canBindPartner` 校验后 UPDATE
- `updated_at=now()`；审计 `case.partners`

- [ ] **Step 3: `GET cases/:id` 附带摘要**

仅当 `a.role==='admin'`（或等价：仅 admin 角色，不只是 coordinator membership）时：

```ts
partners:{
  ivf: ivfRow?{id,name,status}:null,
  postpartum: postpartumRow?{id,name,status}:null
}
```

非 admin：**省略** `partners` 键。
