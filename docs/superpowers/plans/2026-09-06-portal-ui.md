# 客户/案件工作台界面 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐 `components/product/portal.tsx`，让已批准用户在登录后能按角色使用概览、案件详情、报告流转、供者资料库与管理页。

**Architecture:** 单个 `'use client'` 组件树，全部放在 `components/product/portal.tsx`；用内部状态切换视图，不新增路由。数据经既有 `useResource`/`api` 访问 `app/api/[...path]/route.ts`，权限判断完全依赖后端返回的 `can_manage`、`can_review`、`can_publish`、`membership` 等字段，前端不复制授权规则（唯一例外是导航是否显示资料库，该判断抽成 `lib/policy.ts` 的纯函数并加单测）。

**Tech Stack:** Vinext 1.0.0-beta.5、React 19、TypeScript 5.9、Base UI/shadcn 组件（`components/ui/*`）、Cloudflare Worker + D1 + R2、`node --test` 跑纯函数测试。

## Global Constraints

- 设计依据：`docs/superpowers/specs/2026-09-06-portal-ui-design.md`。范围内只改动本计划列出的文件，不改数据库、不改接口协议。
- 私密试用版：界面文案须提示仅提交测试资料，不得新增声称已具备医疗、法律或合规能力的表述。
- 全部界面中英双语，经 `useLocale()` 的 `t(zh,en)`；状态与角色名称一律取 `components/product/common.tsx` 的 `labels`，不另造词。
- 错误提示一律用 `ErrorNotice` / `ActionForm` 内置渲染，错误码文案取 `common.tsx` 的 `errors`；不在界面里拼接后端未定义的错误文案。
- 代码风格跟随现有文件：紧凑单行、单引号、无分号对齐要求以 `npm run lint`（oxlint）与 `npm run format`（oxfmt）为准。
- 客户端组件禁止引入 `@/app/chatgpt-auth`（它 import `next/headers`，仅限服务端）与 `@/lib/server`（它 import `cloudflare:workers`）。退出链接直接写 `/signout-with-chatgpt?return_to=%2F`，阶段常量在门户内自带一份，与 `lib/server.ts` 的 `stages` 逐项一致：`assessment, treatment, transfer, pregnancy, birth, paperwork, paused, loss, closed`。
- 上传限制与后端 `validateUpload` 对齐：单文件 ≤ 8 MiB，仅 `application/pdf`、`image/jpeg`、`image/png`。收件人 1–10 位，必须是案件内已批准的客户成员。
- 目录授权到期日必须在未来一年内（后端 `366 * 86400000` 上限）。
- 当前工作目录**不是 git 仓库**（`git status` 返回 `fatal: not a git repository`）。因此各任务的「提交」步骤按以下方式执行：若用户已执行 `git init` 并接受首次提交，则正常 `git add`/`git commit`；否则跳过提交，仅勾选本计划中的复选框记录进度。
- 每个任务的验收门槛：`npx tsc --noEmit` 零错误、`node --test tests/policy.test.mjs` 全通过、`npm run lint` 无新增告警。

## 现状基线（实施前已确认）

- `npx tsc --noEmit` 当前报 **116** 个错误，绝大多数源于 `lib/server.ts` 的 `export const fail=(status,code):never=>{...}`：TypeScript 的 never 收窄只对**函数声明**或带显式类型注解的常量生效，赋给变量的箭头函数不触发收窄，于是 `if(!x)fail(...)` 之后 `x` 仍为可空。已用独立探针文件验证：函数声明版本收窄成功，箭头常量版本报 `TS2322`。
- 另有三处需要显式类型：`components/product/common.tsx` 中 `res.json()` 返回 `unknown`（第 14、15 行）、`lib/server.ts` 第 121 行 `[...new Set(value)]` 得到 `unknown[]`。
- `node --test tests/policy.test.mjs` 现为 13 passed / 0 failed，可直接作为回归基线。
- 本地 `npm run dev` 收不到 `oai-authenticated-user-*` 请求头（由托管平台注入），浏览器直接访问 `/portal` 只会看到登录卡片。因此本地运行时验证用 `curl` 手动附加身份头做 API 冒烟，界面外观验证放到私密部署之后（交付步骤 7）。
